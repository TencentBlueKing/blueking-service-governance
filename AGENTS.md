## Purpose

* These brief instructions apply to the whole repository. Module-specific guidance lives in the nested `AGENTS.md` files, e.g. `bkms-server/AGENTS.md` and `bkms-cli/AGENTS.md`.
* **Humans** are always responsible for changes being proposed and must pre-review all agentic work before turning it into a PR.

## Repository layout

* `bkms-server/` — Gin REST API service (Go)
* `bkms-cli/` — Cobra-based CLI (Go); npm package `@blueking/bkms-cli` lives in `bkms-cli/npm/`
* `bkms-dockerfile-generator/` — Dockerfile generation tool (Go)
* `libs/bkms-adapter/` — shared adapter library (Go)
* `bkms-ui/` — Vue 3 + TypeScript frontend
* `charts/` — Helm charts

## License headers

This project is open source under the MIT License (see `LICENSE`). **Every newly added source file must start with the project license header.**

* Do NOT write the header from memory. Copy it verbatim from an existing file of the same type, so the comment syntax and wording stay consistent:
    - Go — `bkms-server/main.go`
    - Python — `bkms-server/scripts/platform-build/gen-runtime-images.py`
    - TypeScript / JavaScript / CSS — `bkms-ui/src/main.ts`
    - Vue SFC — `bkms-ui/src/App.vue`
* Comment style and placement per file type:
    - Go, TS, JS, CSS: a `/* ... */` block at the very top, followed by a blank line.
    - Python: `#` line comments, placed after the shebang and any encoding declaration.
    - Vue SFC: a `<!-- ... -->` HTML comment at the very top, before `<template>`.
* Whatever must legitimately occupy the first line keeps its place, and the header goes after it. This applies to Go build constraints (`//go:build`, which stop working if a block comment precedes them), Python shebangs, and a UTF-8 BOM.
* Never copy a license header in from another project. Always take it from a file in this repository.

### Files that intentionally have no header

* Generated files, because regenerating them would drop the header:
    - Go files marked `// Code generated ... DO NOT EDIT` (mockery, swag)
    - `bkms-ui/src/@types/v1/**` (regenerated by `pnpm gen:api:v1`)
    - `bkms-ui/src/components.d.ts` (regenerated by `unplugin-vue-components` on every build)
* `bkms-ui/src/fonts/iconcool.js`, a minified icon sprite asset.

### Enforcement

* In `bkms-ui`, ESLint checks the header on `.js` and `.ts` files through the `codecc/license` rule configured in `bkms-ui/eslint.config.mjs`. Run `pnpm lint` to check and `pnpm lint:fix` to insert a missing header. The rule is deliberately overridden there, because the upstream `@blueking/bkui-lint` preset ships a different project's header text.
* Other file types are not machine-checked, so add the header by hand.
