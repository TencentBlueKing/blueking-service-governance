# bkms 场景用例编写

> 定位：`TEST_SCENARIOS_ROUTES.md` 是**冻结的历史台账**（S1~S19），不再更新。本 skill 服务它覆盖不到的部分——**未来新模块**与**存量用例修复**。`TEST_GUIDELINE.md` 是章程，§3 规范对新模块同样全部适用。

## 两条入口

**入口 A：新模块补测**（ROUTES 未收录的模块/页面）

```
① 摸底判定分支 → ② 路径清单(写进文件头) → ③ 不确定项确认 → ④ 写用例 → ⑤ 变异验证 → ⑥ 归档
```

- ① 通读模块源码，数**用户可感知判定分支**：模式切换、步骤流转、校验通过/不通过、保存成败、确认弹窗、loading/禁用、空态。
- ② V = 判定节点数 + 1；路径清单**写在测试文件头**（新模块不进 ROUTES；若日后模块稳定、维护者认为值得入册，由其自行补录）。
- ③ 不确定项先按业务约定与源码现状做合理假设固化断言，记入文件头 backlog 并找业务负责人确认——不确定不等于停下，但不许假装确定。
- ⑥ 归档 = 文件头注释（承载 V/路径/stub 边界/backlog）+ 踩坑登记 `TEST_PILOT_LOG.md`。**不改 ROUTES。**

**入口 B：存量用例失败修复**

```
复跑定位 → 定性 → 适配或修根因 → 记 TEST_PILOT_LOG
```

- 定性三选一：**业务代码变更**（用例适配新行为，断言按新现状重写）、**用例本身过时/写错**（修用例）、**环境事实**（新坑 → 记 PILOT_LOG）。
- 定性拿不准 = 不确定项，按入口 A ③处理。
- 修复后全量复跑；若是新环境坑，`TEST_PILOT_LOG.md` 登记一行（根因 + 结论 + 示例位置），后来者不再踩。

## 核心规则（违反即返工）

1. 颗粒度以源码判定分支为准，路径清单写进文件头；不虚构「以为有」的交互，逐条对着模板/组件核。
2. 测行为不测实现——role/text 查询、断言用户可见结果；bkui-vue 真实渲染，仅 Message/InfoBox/子组件契约 stub。
3. 写 stub 前先读真实 `defineExpose` 契约并核对同步/异步——Promise 恒 truthy 曾废掉整个校验分支。
4. 消极断言必须有完成信号——先等真实消费点或 UI 信号再断言「未被调用」，否则首检即过漏报。
5. 全绿 ≠ 有效：每个新测试文件注入 ≥3 个业务变异（建议 3~4 个，覆盖四类保护网）确认用例会红，精确还原后复跑全绿。
6. `src/` 原则上零变更——发现 src/ 差异先判断是否变异残留，是则立即还原；真实业务缺陷找业务负责人确认登记，不顺手改业务代码。
