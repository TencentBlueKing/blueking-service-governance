# 特性环境

特性环境可以简单理解为一种**仅对单个应用可见的环境**。普通环境属于工作空间，可被多个应用共同使用；特性环境则归属于创建它的应用，只在该应用的部署、配置和观测等场景中展示，不进入工作空间的公共环境列表，也不能被其他应用访问。

创建特性环境类似于克隆一个已有的普通环境。用户选择源环境并提供展示名称后，平台复制源环境的基础信息和该应用在源环境中的相关配置，使新环境具备与源环境接近的初始运行条件。特性环境创建完成后独立存在，源环境后续发生变化时，不应自动影响已创建的特性环境。

创建时可控制是否复制源环境直接配置的自定义环境变量。副本保留变量名、值、描述和敏感标记，使用新记录，敏感值继续加密存储，之后两边的修改和删除互不影响。

为保证工作负载隔离，平台会为每个特性环境自动生成独立的 `namespace`，用户无需填写或维护。除 `namespace` 以及用于标识特性环境归属、来源的必要信息外，其余环境属性原则上沿用源环境。特性环境拥有独立生命周期，可单独创建和删除；删除前应先清理其中的应用部署。

> 以上是关于特性环境最基础的说明，功能的更多特点，比如特性环境创建后如何管理、删除等，将在之后补充与实现。
